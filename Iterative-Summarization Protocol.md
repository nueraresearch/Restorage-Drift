# **Restorage Drift in Iterative Summarization: A Test Protocol**

*Supplementary Material S1 accompanying “Restorage Drift: A Theory of Information State Evolution Under Repeated Compression and Reconstruction.”*

**Version 1.0.0 — 27 November 2026.** Pre-registration draft; no data collected.

## **1\. What this protocol is for**

Restorage Drift makes claims that are specific enough to fail. This document specifies how to make them fail in a system where the quantities of Section 5 of the theory paper can be measured directly: a language model that summarizes its own summary across repeated cycles.

Each of the theory's four state variables has an operational counterpart here. $K_n$ is manipulated directly, by what the stored text does and does not contain. $E_n$ is scored from that text by blinded coders. $A_n$ is estimated by recovery under a fixed probe procedure. $S_n$ is estimated by the distribution of probe responses. The first two are what the earlier draft of this protocol omitted, and without them the design tests reweighting while assuming the two mechanisms the theory was revised to separate.

The protocol is a companion, not an appendix. It is written to be pre-registered and run as an independent study, and it tests one instantiation of the framework rather than the framework as a whole. The phenomenon under test is restorage drift, in the theory's sense: drift that compounds because reconstructed output is written back as the state the next cycle operates on, instead of the record being preserved alongside it. Where the theory asserts that *some* $C$ and *some* $R$ operate under a resource constraint, this protocol fixes both and asks whether the resulting trajectory behaves as Section 5 predicts.

## **2\. The measurement problem**

Two design features determine whether the experiment measures anything, and both are easy to get wrong.

**The probe must not re-store.** Reconstruction is the operator under test, so observing a cycle cannot itself be a cycle. Each measurement is taken with a verification query whose output is scored and discarded: it never enters the stored state and never becomes input to the next compression. If probe output were fed back, the measurement would be a re-storage event and the observed trajectory would be the probe's, not the system's.

**Probe reactivity is a checkable assumption, not an axiom.** The design includes a low-frequency probe condition (measure only at cycle $K$) against the standard condition (measure every cycle). If $T_d$ differs between them, probing is causally implicated and the every-cycle measurements must be discarded in favor of end-point scoring. This condition is the protocol's own falsification test.

## **3\. Items and priors**

Each item is a short passage containing one target detail $x^{*}$ that is improbable under the model's prior, alongside a high-prior alternative that a reconstructive process could substitute for it. Items are matched on length and on the number of candidate variants scored (four per item), so that $m_n(x^{*}) < \tfrac{1}{2}$ measures the same event across items.

**Prior measurement precedes the loop.** For every item, $q = 20$ reconstructions are elicited from a stripped prompt that omits the record entirely but preserves the question. The empirical distribution over the four candidates is the estimate $\hat P$ used throughout. This is not optional: every prediction in Section 7 is stated relative to $\hat P$, so a protocol that skips it can only report that something moved, not that it moved toward the prior.

**Contamination screen.** An item is retained only if the stripped-prompt reconstructions recover $x^{*}$ no more often than chance allows. With four candidates chance is $1/4$, so $q = 20$ draws give $X \sim \mathrm{Binomial}(20, 1/4)$: an item carrying no training-data advantage yields 5 recoveries on average, with a standard deviation of 1.94. The rule is one-sided at $\alpha = .05$, and the rejection region begins where chance becomes implausible: an item is **discarded** when 9 or more of the 20 reconstructions recover $x^{*}$, which chance alone produces with probability .041, and **retained** at 8 or fewer. A count below chance is not grounds for discarding — the screen asks whether the model already knows the answer, not whether the question is easy — and the rule is fixed before any full-text run, so no item's fate is decided by looking at its chains. An extended prior sample is screened by the same test, with the tail recomputed at its own $q$. Items where the model already knows the answer from training data measure recall, not reconstruction, and they are discarded before the loop begins.

### **3.1 The item record and where the set lives**

**Format.** The item set is one UTF-8 JSON Lines file, one record per line, keys sorted, no blank lines, and the file takes the name of the set it holds: the pack's two construction pilot sets are `items.real.jsonl` and `items.pilot.jsonl`, each with a manifest recording its SHA-256, byte size and record count. Every record carries all of the fields below; a record missing one is invalid rather than defaulted, so the file either matches this schema exactly or fails validation before the loop starts.

| Field | Type | Contents |
| :---- | :---- | :---- |
| `item_id` | string | stable identifier, never reused across versions of the set |
| `passage` | string | the full-text record that enters the loop as $S_0$ |
| `target` | object | `text` (the span exactly as it appears in `passage`), `start` and `end` (0-based character offsets, end-exclusive), `label` |
| `candidates` | array of four | `{label, text}` objects in the fixed order the probe presents them; exactly one is the target |
| `probe` | string | the stripped-prompt question, as sent |
| `ground_truth` | object | `target_label`, `prior`: `{q, counts: [four integers], estimator}` from the prior measurement of this section, and `screen`: `{recovered, q, passes}` under the rule in this section |
| `strata` | object | `length_tokens`, `b2_position` (`inside`, `outside`, or `na`), `fictional` (boolean), `pair_id` (null or the partner's `item_id`) |

**The probe.** One item, one question, four labels, no passage. `probe` is a single user turn that states the question and lists the four candidate labels in their recorded order, without any text from `passage`. The response is parsed to one of the four labels; an answer matching none of them is recorded as `none` and kept in the denominator, never dropped. The same string is used for prior measurement and for in-loop probing, so a difference between the two measurements is a difference in what the model was shown, not in what it was asked.

**Ground truth is mechanical.** An item's ground truth is its target label together with the target's character span, both fixed at construction and checked by script against `passage`. Nothing is left to a rater's judgement of whether a reconstruction preserves $x^{*}$: $m_n$ is the count of the target label among the $q$ probe responses, and the contamination screen is that same count on the stripped prompt. A response is evidence about the four candidates and nothing else.

**The pilot sets are not the study set.** The item text is not printed here and is not in this repository. The pack holds two construction pilot sets—`items.real.jsonl` for the real-world items and `items.pilot.jsonl` for the fictional ones—each of 8 items, each with a manifest recording its digest, byte size and record count. Both are unmeasured: every `prior.counts` is null and no screen verdict has been applied. They exercise construction, offsets, strata, probe rendering and pairing, and no outcome computed from them enters a confirmatory analysis or moves a threshold in Section 7, because those thresholds are fixed by the binomial arithmetic of Section 7.1 and not by pilot data. Their size is a property of construction rather than of the study: at eight items no count-based line in Section 7.1 is even definable, and the two sets together leave too little power for Prediction 1 to be worth running.

**The registered set.** The confirmatory set is the forty-item run of Section 9, built to the quotas of Section 3 and the construction standard, measured at $q = 20$, screened under the rule of Section 3, and paired after measurement. It is one UTF-8 JSON Lines file with its own manifest recording its digest, byte size and record count, and the registration records those three values, so "the item set" names one byte sequence rather than a description of one. It is released when the first chain is analysed. Publishing it beside the theory would place the item text in the training data of any model that later reads the repository, which is exactly the contamination the screen above is meant to detect; keeping it in the registration is what keeps that screen meaningful.

## **4\. Arms**

| Arm | Question it answers | Manipulation |
| :---- | :---- | :---- |
| **A — Baseline chain** | Does drift occur at all? | $S_{n+1} = R(C(S_n), P)$ at budget $W$ |
| **B — Verbatim transport** | Is compression necessary? | Copy the record without paraphrasing: B1 identity when the record fits the budget, B2 mechanical truncation to $W$ |
| **C — Star topology** | Is re-storage necessary? | Each cycle recompresses $S_0$; no output is re-stored |
| **D — Shared-prior pairs** | Is the attractor prior-determined? | Item pairs with the same $\hat P$ but different $x^{*}$ |
| **E — Fictional items** | Where does the prior come from? | Items with no training-data prior; all prior structure supplied by the prompt |

Arm B and Arm C are the two controls the framework cannot survive without. Arm B isolates compression: if verbatim transport drifts, the mechanism is not compression. Arm C isolates re-storage: if the star condition drifts as far as the chain, accumulation across cycles is not what produces the effect, and the re-storage requirement of Section 2 of the theory is idle.

**Arm B in detail.** The control is only meaningful if it says what is copied when the record is longer than the budget, and a record longer than $W$ cannot be transported verbatim at $W$ without losing something. Arm B therefore splits. In **B1 (identity)**, items are constructed so the full record fits the largest budget and the entire record is copied unmodified at every cycle: nothing is dropped, nothing is paraphrased, and $C$ is the identity map. B1 asks whether re-storage alone, with no compression at all, produces drift. In **B2 (truncation)**, the record is cut mechanically at the token boundary to the summary budget and the retained span is copied exactly, under an instruction to reproduce it character for character. Truncation is lossy but not reconstructive: it removes content without asking the model to fill anything in.

Within B2, the position of $x^{*}$ is a controlled factor rather than a nuisance—either it falls inside the retained window, or it falls outside and is dropped. The two cases answer different questions. If $x^{*}$ is retained and still drifts toward the prior, reconstruction is operating on intact text, which is the claim that compression and reconstruction are separable. If $x^{*}$ is dropped, nothing about it survives the first truncation: under the absorbing-support assumption of Section 5.4 it leaves the active set, and reconstruction cannot generate a candidate that is no longer active, so $x^{*}$ cannot return at any later cycle.

Arm D is the sharpest test of the attractor claim in Section 5.5, provided the chains are matched on surviving candidates. Because the closed form's limit is a function of the prior and the retained set alone, two chains with the same $\hat P$, different starting points, and the same surviving set should converge on the same terminal distribution. Divergence under those conditions is evidence that the recursion is the wrong model even where drift is plainly present; divergence between chains whose surviving sets differ is the model's prediction rather than a failure of it.

## **5\. Conditions**

- **Budget** $W \in \{15, 30, 60\}$ tokens for the summary, held fixed within a chain and across its cycles.
- **Reconstruction length** fixed at $W_R$ across all arms, so that summary length is the only varying capacity parameter.
- **Probe frequency** every cycle (primary) or terminal only (reactivity check).
- **Compression mode**, crossed with arms where possible: paraphrase, orthographic perturbation, and qualifier deletion, corresponding to the three modes of Section 3 of the theory.
- **Target position** (Arm B2 only): whether $x^{*}$ falls inside or outside the retained window.
- **Sampling temperature** fixed and reported; model snapshot pinned by version string for the whole run.

## **6\. Measures**

All measures are computed from $m_n$, the distribution over the four candidates estimated from $q$ samples at cycle $n$: 20 by default, extended as described in Section 9 when the estimate lands near the one-half boundary.

- **Drift:** $d_n = 1 - m_n(x^{*})$.
- **Threshold:** $T_d = \min\{n : m_n(x^{*}) < \tfrac{1}{2}\}$, right-censored at $K$ when never reached. Censoring is a result, not a missing value, and it is analyzed as such.
- **Overtaking landmark:** $T_o = \min\{n : \exists\, y \neq x^{*}, \; m_n(y) > m_n(x^{*})\}$, the first cycle at which a rival's mass exceeds the original's. $T_d \leq T_o$ wherever $T_o$ is finite. Where no rival ever overtakes, $T_o = \infty$ and the inequality holds trivially: a candidate can fall below one half while still holding the largest single share, which four scored candidates make possible and two do not. The two therefore coincide only in the two-candidate case, and $T_o$ is reported descriptively alongside $T_d$ rather than as a primary outcome: where they diverge, the gap is the interval in which the original retains a plurality but not a majority.
- **Attractor:** $\hat A$, the modal candidate at cycle $K$, compared against $\arg\max_x \hat P(x)$. Where $\hat P$'s modes are tied, the comparison is against the co-modal set rather than a single candidate.
- **Attractor distance:** total variation between terminal distributions of paired chains in Arm D.
- **Availability landmark:** $\hat T_A = \min\{n : x^{*} \text{ not recovered at cycle } n\}$, right-censored at $K$. A cycle counts as non-recovery only when none of the $q$ probe responses matches $x^{*}$ under the coding rule; one match is evidence that the candidate remains available. Because a finite probe can miss an available candidate, loss is required on two consecutive cycles before $\hat T_A$ is set, and single-cycle misses are reported separately rather than counted as recovery.

**The probe distribution is a proxy for the state, not the state.** $m_n$ and everything computed from it — $T_d$, $\hat A$, the mode contests of Section 7 — observe what the model says under one fixed procedure applied to a stored text. $S_n$ of the theory is a distribution over candidates internal to the system; $m_n$ is a distribution of answers, and answers are generated from the model's prior knowledge of the subject as well as from the text in front of it. The two coincide only if the text is doing the work the theory attributes to it, which is precisely what Prediction 9 tests. Every verdict in Section 7 is therefore a claim about response behaviour under the probe given the stored text, and none of them is a claim about the model's internal state.

**Availability is a proxy, not the latent set.** $\hat T_A$ observes response behaviour under a fixed procedure. It is not $T_A$ of Section 5.6 of the theory, which is defined on the active set $A_n$, and the two diverge whenever the model can recover a candidate it no longer represents in the stored text. The operational quantity is therefore reported as "not recovered under the probe procedure" and never as "absent from the model".

**Evidence is scored independently of response frequency.** If $E_n(x^{*})$ were estimated from the proportion of correct responses, the evidence mechanism would be circular and the theory unfalsifiable. The stored summary of each cycle is therefore scored from its text alone, by two coders blind to arm, cycle number, and every probe response, on a four-point rubric: 0, no statement bearing on $x^{*}$; 1, the passage asserts a rival inconsistent with $x^{*}$; 2, the passage is compatible with $x^{*}$ but neither asserts nor excludes it; 3, the passage asserts or entails $x^{*}$. Coding is completed and frozen before response data are decoded, so that no coder can know which scores would favour which prediction. Disagreements of more than one point are adjudicated by a third coder, also blind. Agreement is reported as Krippendorff's $\alpha$ for ordinal data, and $\alpha < .80$ is treated as a failure of the measure rather than as a finding.

**From scores to a landmark.** With the operational threshold fixed at $\hat\varepsilon = 2$, a candidate counts as unsupported when both codings fall below "compatible". Let $\hat E_n(x^{*})$ be the higher of the two codings, so that the landmark fires only on coder agreement, and define $\hat T_E = \min\{n : \hat E_n(x^{*}) < \hat\varepsilon\}$, using the same two-consecutive-cycle rule and the same right-censoring at $K$. This is a text-level quantity. It becomes evidence about the model only if the response distribution moves with it, and Prediction 9 states what that requires.

## **7\. Pre-specified predictions**

1. **Directionality.** In Arm A at $W = 15$, the probe's modal answer $\hat A$ differs from $x^{*}$ and equals $\arg\max_x \hat P(x)$ in at least 28 of 40 items (70%); at most 23 of 40 (57.5%) is failure. The verdict is about what the model answers under the probe applied to the stored text, not about its internal state (Section 6). The no-effect rate is one half: each item is a contest between two named answers—the detail the record asserts and the answer the model's prior prefers in its absence—and a system with no re-storage effect is exchangeable between them, so the count is a fair coin per item. The foils are not third and fourth contenders: they are constructed to be implausible attractors, and an item answered with one is scored against support rather than dropped. Section 7.1 gives the argument, and says why one quarter belongs to Prediction 5a's contest rather than to this one. The support line rejects that rate at $\alpha = 8.3 \times 10^{-3}$.
2. **Budget ordering.** $T_d(W{=}15) < T_d(W{=}30) < T_d(W{=}60)$ in paired comparisons within item. Support requires both adjacent hazard ratios below 1 with 95% intervals excluding 1; either at or above 1 with an interval excluding 1 is failure.
3. **Re-storage.** $T_d$ in Arm A is shorter than in Arm C at matched total token cost, and a share of Arm C chains is censored at $K$. Support requires a hazard ratio below 1 with a 95% interval excluding 1 and at least 20% of Arm C chains censored; a hazard ratio at or above 1 with an interval excluding 1, or censoring below 5% while at least half of the Arm A chains cross, is failure.
4. **Compression necessity.** B1 shows no threshold crossing ($m_K(x^{*}) \geq \tfrac{1}{2}$ throughout), and B2 with $x^{*}$ retained behaves like B1. B2 with $x^{*}$ dropped crosses at $n = 1$ instead: the detail is absent from the first summary rather than eroding across cycles, so $T_d = 1$. The later cycles reconstruct nothing: B2 copies the retained span character for character, so $x^{*}$ never re-enters the stored state, and any mass at $x^{*}$ in a later measurement comes from the probe generating it out of the model's prior rather than from the state. The contrast is the point—instant loss and gradual drift are different trajectories, and only the second requires the recursion. Support requires $m_K(x^{*}) \geq \tfrac{1}{2}$ in at least 95% of B1 chains, crossing in no more than 10% of the B2 chains that retain $x^{*}$, and $T_d = 1$ in at least 90% of the B2 chains that drop it. Crossing in 20% or more of B1 chains, in 40% or more of B2-retained chains, or $T_d > 1$ in 30% or more of B2-dropped chains, is failure. These are tolerance lines rather than chance-level tests: B1 copies the record unchanged, so any crossing is a defect and 5% is the allowance for probe and coding error.
5. **Attractor prior-determination.** Arm D pairs converge, and their terminals sit on the prior's mode. Support requires both in at least 14 of the 20 pairs: the two terminal distributions closer to each other than either is to its own starting state, and the terminal mode equal to $\hat P$'s mode (a co-modal set counts as agreement when $\hat P$'s modes are tied). At most 9 of 20 on either clause is failure. The clauses are counted separately and against different no-effect rates — one in four for the mode, one in three for the ordering, that being the rate exchangeability gives it when a pair shares nothing — and a result that supports one clause and fails the other is reported as indeterminate, not as partial support.

   Distance is reported rather than scored, and the reason is Proposition 3. The limit is $P^{\beta/(1-\alpha)}$ normalized, so total-variation distance from a terminal to $\hat P$ depends on parameters the study does not observe: an earlier draft of this protocol made distance the criterion at 0.20, which the model's own illustrative settings violate at 0.29. Monotone tempering preserves the ordering of candidates, so the mode is the part of the limit the model fixes; each terminal's distance to $\hat P$ is reported alongside the exponent $\beta/(1-\alpha)$ that reproduces it.
6. **Prior source.** Arm E drifts, but less than Arm A: fictional items retain $x^{*}$ longer because no training prior supplies the alternative. Support requires a hazard ratio below 1 with a 95% interval excluding 1 and a median $T_d$ difference of at least two cycles; a hazard ratio at or above 1 with an interval excluding 1 is failure.
7. **Mode sensitivity.** Orthographic and qualifier-deletion conditions cross at different $T_d$ than paraphrase within the same item: at least two cycles of difference in median $T_d$ for each contrast, with the sign agreeing across the two modes in at least 28 of 40 items. Sign agreement in 23 or fewer is failure; the no-effect rate here is one half, since agreement between two independent contrasts is a coin flip.

8. **Availability order.** $\hat T_d \leq \hat T_A$ wherever both are finite, in every arm: a candidate with zero reconstructed mass has already lost the majority, so a chain reporting $\hat T_d > \hat T_A$ has a coding or decoding fault and is counted against the pipeline rather than reported. In B1 the record is identical at every cycle and $x^{*}$ is in it, so both landmarks are censored for most chains; in B2 with $x^{*}$ dropped, $\hat T_d = \hat T_A = 1$. Because this prediction is a check on the pipeline rather than a claim about drift, its criterion is a tolerance: at most 2% of chains may violate the order, and above that the arm is reported as a coding or decoding fault and no prediction is scored from it.
9. **Evidence precedes availability.** In Arm A at $W = 15$, $\hat T_E \leq \hat T_A$ with a lag of no more than two cycles, and both are censored in B1. A chain whose text support collapses while the response distribution holds is reported as candidate generation or parametric knowledge, not as evidence retention. Support requires $0 \leq \hat T_A - \hat T_E \leq 2$ in at least 90 of the 120 coded chains of Arm A at $W = 15$ (three replicates per item, Section 8), and both landmarks censored in at least 90% of the coded B1 chains; 84 or fewer is failure. The no-effect rate is .27, the share of a three-cycle window when the two landmarks are independent and timed uniformly over the horizon.

Prediction 2 depends on the coupling assumed in Section 5.7 of the theory, and stated there as a hypothesis—that a smaller $W$ raises $\beta$ relative to $\alpha$—rather than on the framework alone, so a failure of ordering bears on that coupling rather than on the recursion.

**From criteria to verdicts.** Each prediction now carries its own numeric criterion, so every result is scored as support, failure, or indeterminate — the last for any outcome in the band between the two, reported as such and counted as neither. Intervals are reported throughout: Wilson 95% intervals for proportions, hazard ratios with 95% intervals from the survival model of Section 8, and item-level bootstrap intervals for paired medians. A measured Krippendorff $\alpha$ below .80 voids the predictions that depend on the evidence score, before any outcome is examined.

**Multiplicity.** The five count-based rules of Section 7.1 — 1, 5a, 5b, 7 and 9 — carry the confirmatory weight, and they make one family of four hypotheses: 5a and 5b are joined by intersection-union, each scored at $\alpha = .01$, so the pair counts once. Holm–Bonferroni holds the family-wise error at .05: the smallest $p$ is compared with .0125, the next with .0167, then .025 and .05, and a prediction is called supported only when it clears its step. A result that clears .01 but not its Holm step is reported as not supported rather than as a near miss, because the ordering is fixed by the $p$-values and the correction therefore costs less than a flat .0125 on every test. The other four predictions are not in the family and are not treated as significance tests: 2, 3 and 6 are reported as hazard ratios with 95% intervals, and 4 and 8 are tolerance lines whose purpose is to catch a defect in the pipeline. Within Prediction 2 the two adjacent budget contrasts are a family of their own, Holm-adjusted at .05. No composite score is formed across anything, and the count of indeterminate verdicts is reported alongside the corrected ones.

Where the criterion is a hazard ratio the interval decides: a point estimate below 1 with an interval spanning 1 is indeterminate, not supportive, and is reported that way.

### **7.1 How the thresholds were set**

Every count-based line in Section 7 was fixed before any data by a binomial calculation, not by convention, and each is a three-outcome decision rule. Three quantities are set in advance per prediction: the rate $p_0$ that a system with no effect would produce, the minimum effect $p_1$ worth acting on, and two lines. The pair is chosen so that the support line keeps power at $p_1$ at or above .90 wherever the unit count and the no-effect rate allow it, the failure line keeps $\beta \leq .10$, both reject $p_0$ at $\alpha \leq .01$, and a band of at least 4% of the units separates them, so that a genuinely ambiguous result is reportable rather than forced to a verdict. The achieved values are given per prediction in the table below, and where the unit count or the no-effect rate cannot deliver .90 the table reports the power reached instead. Counts between the two lines are indeterminate.

| Prediction | $n$ | $p_0$ | $p_1$ | Support | Failure | Power |
| :--- | :---: | :---: | :---: | :---: | :---: | :---: |
| 1 Directionality | 40 | .50 | .75 | 28 | 23 | .82 |
| 5a Attractor mode | 20 | .25 | .75 | 14 | 9 | .79 |
| 5b Pair ordering | 20 | .33 | .75 | 14 | 9 | .79 |
| 7 Mode sensitivity | 40 | .50 | .80 | 28 | 23 | .96 |
| 9 Evidence lag | 120 | .27 | .80 | 90 | 84 | .93 |

$n$ is the number of units — items, pairs, or the coded chains of Prediction 9 — with support a lower bound on the count and failure an upper bound. The error rates behind each line, by row: **1** $\alpha = 8.3 \times 10^{-3}$, $\beta = .012$; **5a** $3 \times 10^{-5}$ and $3.9 \times 10^{-3}$; **5b** $8.8 \times 10^{-4}$ and $3.9 \times 10^{-3}$; **7** $8.3 \times 10^{-3}$ and $1.0 \times 10^{-3}$; **9** $1.0 \times 10^{-27}$ and $5.9 \times 10^{-3}$. The largest $\alpha$ is therefore .0083, at Predictions 1 and 7, and the largest $\beta$ .012, at Prediction 1, both inside the .01 and .10 ceilings stated above. Those are the levels the table is powered at, and .01 is stricter than the .0125 that the first Holm step of Section 7 allows, so every power in the table is a lower bound on the power the procedure actually delivers; the correction can only widen the rejection region a row was computed against.

**Prediction 1's no-effect rate was the wrong one.** The one-in-four floor describes a draw among four candidates, which is the right null where the mode contest is against all of them (Prediction 5a, below). Prediction 1 is not that contest. It names the two answers it puts against each other—$x^{*}$, which the record asserts, and $\arg\max_x \hat P(x)$, which the prior prefers when the record is absent—and asks which of them the probe returns. The foils are not third and fourth contenders: they are constructed to be implausible attractors, and an item where one takes the modal answer is scored against support rather than dropped, so a foil reduces the count instead of splitting it. Under a null in which the record's assertion and the prior's preference are on equal footing, each is as likely as the other to be the answer returned, which puts the per-item rate at one half, and no admissible null puts it higher: the foils have no designed advantage, so where they take mass the rate falls below one half rather than above it. A null of one quarter asserts what the construction rules deny—that the foils are as probable as either attractor—and it is the null Prediction 5a needs, because there the mode contest really is against all four. One half is the rate, and 26 of 40 rejects it at $\alpha = .040$, outside the .01 ceiling. The line is now 28 of 40 — $\alpha = 8.3 \times 10^{-3}$, failure at 23, the band at 10% of the items — and the power it costs, .95 to .82 at $p_1 = .75$, is the price of forty items at this null. 

**Why one half, and not zero.** A strict null would hold that the record is intact, so the probe returns $x^{*}$ and the rate is near zero. That null is not available here for a reason that has nothing to do with convenience: the probe is a proxy for the state rather than the state (Section 6), its error rate is not bounded in advance, and at a rate of zero a single stray answer would count as evidence of drift. One half is therefore the least favourable rate the design can defend, and calibrating at the least favourable null is what makes the line honest in the direction that matters: if the true no-drift rate sits below one half, the threshold at 28 of 40 is conservative and every power in this table is a lower bound, whereas calibrating at one quarter would let a system sitting at the true two-attractor rate clear a line drawn for a much rarer event. Arm B1 measures the rate instead of assuming it—Prediction 4 requires it never to cross, and its mode-agreement rate is reported as the observed no-drift rate—so the assumption is argued here and checked there, and a confirmatory line is still not set from data the study has not collected.

Prediction 5 appears twice because its two clauses share a count line but not a no-effect rate, and the earlier draft's single row quietly assumed the mode clause's anchor for both. The mode clause is a Bernoulli event: a terminal mode drawn at random among four candidates lands on $\hat P$'s mode one time in four, so $p_0 = .25$. The ordering clause is not an event of that kind, and scoring it against .25 would be a mistake; its null is exchangeability. When the four distributions of a pair carry no information about one another, their three pairwise distances are exchangeable, so the terminal-to-terminal distance is the smallest of the three with probability $1/3$ — that, and not .25, is the rate the ordering clause is scored against. At the shared 14-of-20 line $\alpha$ is therefore $3 \times 10^{-5}$ for the mode clause and $9 \times 10^{-4}$ for the ordering clause, with power .79 for both, since power depends on $p_1$ alone. Support requires both clauses, so the prediction's own error rate is no larger than either and no adjustment is needed between them; neither clause is scored as a continuous distance, and a split verdict is reported as indeterminate rather than as partial support.

Prediction 9's unit count is the coded subsample, not the arm: 40 items times the three replicates per item and cell that Section 8 codes, so Arm A at $W = 15$ yields 120 chains and not the 400 it runs. An earlier draft set that line at 280 of 400, which no outcome of the coded subsample could reach.

Read against a null, the Prediction 1 rule behaves as intended: at $p = .5$ it returns failure on 87% of runs and support on under 1%, and with $p = .75$ it returns support 82% of the time and failure on 1.2%. A 200,000-run Monte Carlo of that rule reproduces these rates.

The failure line is where earlier drafts of this protocol went wrong, and the error is worth naming because it is easy to repeat. Setting failure at the rate the prediction was supposed to beat — twenty of forty, the no-effect rate itself — makes failure fire on 56% of runs in which nothing is happening, and on none of the runs the study is powered for. A verdict that arrives half the time under the null, and cannot arrive when the effect is present, carries no information in either direction. The lines above sit a full step below $p_1$ instead, so failure means the effect is at least that far beneath the level the prediction needs, and it fires almost always when the effect is absent.

Three of the nine predictions are not count-based. Predictions 4 and 8 are mechanical checks on the pipeline, and their lines are tolerances for measurement noise rather than chance-level tests. Predictions 2, 3 and 6 are decided by hazard ratios with 95% intervals, so their operating characteristic is interval width: their power depends on the number of crossing events and cannot be fixed by a binomial calculation in advance, which is why the budget-ordering contrasts are the ones most exposed to a small item set. Prediction 5's power is the lowest in the table (.79) for the same reason at a smaller scale — Arm D yields only 20 pairs — and it is the prediction most worth adding items to if the minimal slice suggests the full run can afford them.

## **8\. Analysis plan**

$T_d$ is a censored time-to-event measure, so the primary analysis is a discrete-time survival model with cycle as the time axis: a mixed-effects logistic regression of crossing at cycle $n$ on budget, arm, and their interaction, with random intercepts for item and replicate. Chain and star are compared on the survival curve, not on mean $T_d$, because censoring makes means misleading when many chains never cross. $T_o$ is computed from the same distributions and reported descriptively; it is not modelled.

Attractor identity is analyzed separately as a categorical outcome at cycle $K$. Arm D is analyzed as a paired comparison of total-variation distances.

$\hat T_A$ is analysed exactly as $T_d$: discrete-time survival, same specification, with the paired difference $\hat T_A - \hat T_d$ reported per arm. The theory constrains the sign of that difference and nothing else about it, so the sign is checkable without fitting a mechanism, and a sign violation is a defect report rather than a result.

Evidence scores are fixed before outcomes are examined, and $\alpha$ is reported alongside them. Because coding is the expensive step while probing is the frequent one, the evidence measure is estimated on a prespecified subsample rather than on every chain: all cycles for three replicates per item and arm-cell, which yields $\hat T_E$ per chain with its precision reported. At 40 items that subsample is 120 coded chains per arm-cell and 720 in total, so the chain count a prediction may use is the coded one rather than the arm's full 400.

The analysis plan, prediction list, item set, and prompts are to be registered before data collection, the item set in the form specified in Section 3.1. Because the theory's predictions are specific enough to be fitted after the fact, a study run without prior registration would not test them.

## **9\. Power, cost, and the minimal slice**

Replicates: $m = 10$ chains per item per condition; cycles: $K = 10$; probes: a base of $q = 20$ samples per measurement, taken every cycle in the primary condition and extended to 60 whenever the estimate lands in $[0.35, 0.65]$. The table prices that rule at an expectation of 20% of measurements in the band, which is $20 + 0.2 \times 40 = 28$ samples per measurement.

Measurement costs twenty times more than generation. An earlier draft of this section counted one probe call per measurement instead of $q$, understating the probe total by exactly that factor:

| | Minimal slice (4 items) | Full run (40 items) |
| :------------------------------------ | :---------: | :---------: |
| Summarization calls (6 arm-cells × items × 10 cycles × 10 replicates) | 2,400 | 24,000 |
| Probe calls (one measurement per cycle, 28 samples expected per measurement) | 67,200 | 672,000 |
| Total calls | 69,600 | 696,000 |
| Approximate tokens (about 110 per summary, about 100 per probe) | 7.0M | 70M |

Probes are about 96% of both calls and tokens, so this is a measurement budget far more than a generation budget, and the cheapest thing to cut is probe frequency rather than cycles or items. Money cost depends on the provider's per-token pricing and the input/output split; the token counts above are what to price.

A third cost does not appear in the table and is larger than either call count in person-hours: scoring. Two coders over the subsample described in Section 8 is 720 stored texts scored twice — 1,440 codings — for the minimal slice, and 7,200 texts scored twice — 14,400 codings — for the full run, at roughly a minute each, or about 24 and 240 hours. That, rather than the API bill, is what limits the evidence measure, and it is why the measure is subsampled rather than applied to every chain.

The 28 samples is an expectation, not a bound, and the assumption behind it is worth naming: the band is entered by cycles whose estimated mass sits near one half, which in this design is a minority, because early cycles sit near 1 and late ones near 0. If 10% of measurements land in the band the probe count is 57,600 and 576,000; at 30% it is 76,800 and 768,000; if every measurement needed the 60-draw ceiling it is 144,000 and 1,440,000. The minimal slice measures the actual share, and the full run is costed from it before the budget is committed, so the expectation is revised rather than assumed twice.



**That ratio exposes the design's real constraint.** With $q = 20$, the standard error of an estimated proportion near one half is $\sqrt{0.25/20} \approx 0.11$. A threshold decision at $0.5$ made on such an estimate will misclassify cycles close to the boundary, and because misclassification is most likely exactly where $T_d$ is determined, it can reorder conditions that differ by a single cycle. The protocol therefore samples sequentially: 20 draws first, extended to 60 whenever the estimate falls within $[0.35, 0.65]$. Most cycles sit far from the boundary—early ones near 1, late ones near 0—so average cost stays close to the low end while boundary decisions get three times the samples.

The count-based thresholds carry their own power, tabulated in Section 7.1; the survival claims do not, and are decided by interval width. The minimal slice is not scored against them — with four items, no support line in Section 7.1 is reachable — it establishes feasibility, the share of measurements that land in the adaptive band, and the direction of effect. The full run at 40 items is what the thresholds are set for, including the budget-ordering comparison. Both are feasible on a single API budget without institutional resources, which is part of why summarization is the right test bed: Section 6 of the theory names it as an instance, so the cheapest available system is also one the framework claims.

## **10\. What this design cannot show**

- **One model is not a class of systems.** A result in one model family constrains that family. It does not establish drift in human memory, organizations, or cultural transmission, and the theory's cross-system hypotheses remain untested by it.
- **The evidence score is textual.** It measures support in the stored text, not evidence inside the model. Where text support and response behaviour disagree, the protocol can report the disagreement but cannot say which latent variable moved.
- **Summarization is not memory.** Nothing here bears on reconsolidation or on biological capacity limits; the token budget is a capacity parameter by analogy, not by measurement.
- **The items are not the Mandela Effect.** The protocol tests whether prior-favored variants displace improbable ones under repeated compression. It does not test whether any historical misremembering arose that way.
- **A null result does not falsify the framework.** It falsifies the claim that *this* $C$ and *this* $R$ produce drift under *these* budgets. The framework's generality is what makes it hard to kill, and this protocol is deliberately aimed at the narrow, killable part.

## **11\. Data availability**

No data were collected for this protocol, and none are reported here. The item set exists only in pilot form: the pack holds two unmeasured construction sets, `items.real.jsonl` and `items.pilot.jsonl`, and the forty-item confirmatory set is built and screened before any chain is run and registered under the manifest that identifies it (Section 3.1). Neither is in the repository that carries the theory and this protocol, because item text published beside them enters the training data of any model that later reads the repository — which is the contamination the screen of Section 3 exists to detect, so publishing the set there would defeat the screen that justifies using it. The confirmatory set is released when the first chain is analysed.

Nothing else exists yet. The chains, probe responses and scores described in Sections 6 to 8 are produced by the run; they are deposited, in the classes and at the points the registration fixes, together with the analysis code, when it executes.
